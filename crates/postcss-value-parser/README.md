# `postcss-value-parser`

> Part of the
> [StyleX SWC Plugin](https://github.com/Dwlad90/stylex-swc-plugin#readme)
> workspace

## Overview

A loose scanner for CSS declaration values. It reads a value into words,
spaces, separators, strings, comments and functions, and every token keeps the
characters the author typed — hex spelling, letter case, quote character and
whitespace positions all survive.

## Why it has a crate to itself

It is somebody else's work. It is left reading the way it was written rather
than idiomatised, and a crate boundary says so in a way a directory name
cannot: nothing in here is StyleX logic, and nothing in here depends on
anything that is. It has no dependencies at all.

## Why the looseness is the point

A StyleX class name is a hash of the canonical declaration text, so that text
is a compatibility contract. A token here is an arbitrary blob rather than a
spec-conformant CSS token — a percentage, a signed dimension and a number in
exponent notation are each one token — and nothing in the scanner understands
what a hex colour is, so nothing in it can shorten one. What no caller
deliberately rewrites comes back byte for byte.

It never rejects. Unclosed functions, unclosed strings and unterminated
comments are recorded as flags on the node they belong to, which is what lets a
value written in syntax newer than the compiler's knowledge pass through
unharmed. There is no error type and no input that produces one.

Depth is the exception, and the one obligation on an embedder. The scan is
iterative and survives any nesting, but spelling a tree out, walking it and
dropping it all recurse once per level, so a deep enough value exhausts the
stack — an abort in Rust, where the JavaScript throws a `RangeError`. Bound
nesting depth before parsing; `stylex-css` rejects past 64.

## What it offers

| Function                                 | Answers                                   |
| ---------------------------------------- | ----------------------------------------- |
| `parse`                                  | a value into a node list                  |
| `stringify` / `stringify_node`           | a node list, or one node, back into text  |
| `stringify_with` / `stringify_node_with` | the same, with a per-node override        |
| `walk`                                   | every node, outside-in or inside-out      |
| `unit`                                   | a word split into its number and its unit |
| `ValueParser`                            | the three above hung off one parsed value |

Source offsets are on every node and count **bytes**, not UTF-16 code units.
Their consumers compare them against each other, never against a JavaScript
index.

## Tests

Expectations are generated by running the JavaScript this stands in for, never
written by hand. Regenerate after adding an input to the generator:

```sh
pnpm run --filter=@stylexswc/postcss-value-parser generate:value-parser-cases
```

`generate:value-parser-cases:check` diffs a fresh run against what is
committed, so the table cannot drift unnoticed.
